# ClearHold collaboration preferences

The project owner is a software engineering student who understands programming and is learning production backend architecture, DevOps, deployment, and security. When explaining implementation or reporting completed work:

1. Start with a simple explanation of what changed and why it was needed.
2. Explain its concrete effect on ClearHold.
3. Define new technical terms in plain English before relying on them.
4. Separate completed work, remaining work, and important risks.
5. Give exact next steps the owner needs to perform.
6. Explain what important commands do, instead of only listing them.
7. Use practical examples for difficult backend and deployment concepts.
8. Keep the main explanation concise; put detailed engineering notes in a separate section when useful.
9. State security concerns and technical limitations plainly.

The owner wants to understand and defend each major technical decision in a software engineering interview. Explain the reasoning behind significant design choices, including the failure cases and tradeoffs they address.
